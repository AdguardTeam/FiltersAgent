Treat the user-provided issue screenshot as the primary definition of the defect. Reporter annotations such as arrows, boxes, circles, and highlights identify the reporter-defined target. Treat the annotated element as the complaint even when it is embedded in navigation or looks like ordinary promotional or sponsored content. Track that same annotated target through the unfiltered and prepared environments; do not replace it with a different ad, placeholder, or advertising symptom. Treat it as an example of a defect pattern that may repeat elsewhere on the page, not as a single coordinate. Inventory every matching instance across full-page tiles.
Distinguish a visible ad creative from an empty reserved ad container or layout gap. Explicitly inventory anomalous empty whitespace and ad placeholders, recording their approximate vertical bounds and nearby visual landmarks in each relevant tile. Sponsored navigation or ordinary sponsored content is not itself an ad placeholder: a visible sponsored link is not proof that the reporter-defined blank-space defect is absent. Do not substitute a different advertising problem seen on the current live page.
For a removable ad or leftover, try a standard domain-scoped element hiding `##` rule first. Use CSS injection `#$#` only after browser evidence proves that element hiding breaks layout or that the page must preserve an intentional nonzero gap. Use ExtendedCSS or a scriptlet only when simple rules do not work.
Anchor a cosmetic selector on something stable and specific to the target: a meaningful class or id, the target's own content such as `:has(a[href^="https://advertiser.example/"])`, or a stable neighbour such as `.site-header ~ div`. A selector made only of structure and attribute presence, such as `body > [id][class*=" "]`, is fragile: it can match exactly one element on this page and still hide legitimate blocks on other pages of the site. When the ids and classes are randomized, anchor on content — the advertiser link, image source, or text the ad always carries.
A behavioral ad defect — a click that opens an ad tab or window, or a scripted redirect — cannot be expressed as element hiding: the standard fix is a scriptlet, for example `<reported-site>#%#//scriptlet('prevent-window-open')`; consult the `scriptlet` guidance topic for exact syntax. Prove that mechanism instead of the pixels: an `interact_page` rehearsal in the unfiltered session showing the click opening the ad tab or window is the strongest evidence for this class. Pass that click to `apply_rule` as `revealSteps`: every phase performs it, and the `revealSteps` result reports how many pages each phase opened. The phase screenshots cannot show a tab that did or did not open, so when the vision review stays inconclusive, finish with `analysis_only` that records the rehearsal evidence, the per-phase `revealSteps` counts and the exact scriptlet candidate for human review.
When the symptom is produced by a loadable resource you can see in `get_network_log` — a third-party vendor script (a consent/CMP platform, an anti-adblock or ad-recovery loader such as `html-load.com`, or a push-notification or tracking vendor) or a first-party ad/consent plugin or asset (for example `||site/wp-content/plugins/…`, `||site/static/…js`, `||site/push-subscribe/`) — prefer a network rule that stops the loader over hiding the element per site. Read the request that renders the symptom from the `requests` inventory (host, path, resource type, thirdParty flag): a `thirdParty` host is a shared vendor, a first-party host is a page-owned plugin or asset. For a third-party vendor host, extend its `||vendor-host^$domain=…` network family if one already exists (that is how maintainers resolve a consent or CMP banner and every other shared-platform symptom); otherwise write `||vendor-host^$domain=<reported-site>`. For a first-party path, write the basic network rule `||site/path` once the repository's policy allows it, and do not add `$domain` to it only to make it look narrower; add `$script`, `$domain`, or other modifiers only when browser evidence or compatibility requires them.
Element hiding remains the default for a symptom baked into the served HTML with no distinct request behind it. Do not block a shared video-player or ad-framework SDK (for example an `imasdk`/`ima3.js` loader, `googlevideo`, or a `$redirect` target) with a fresh network rule; that collateral risk is human-review territory, so finish `analysis_only` with the candidate for such a resource.
